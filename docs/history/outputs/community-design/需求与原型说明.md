# Duck Studio 配色广场：需求与原型

2026-10-22 · 设计交付，供 GPT-6.1 SOL / Ultra 实施。

## 目标

让使用同一份 XGO Duck V2 的人分享完整配色，评价作品，并一键复制喜欢的方案到现有涂装台，继续修改、保存和发布。当前专注这只机器鸭，不增加任意模型导入。

用户已经提出的需求：
- 现有涂装台保留，增加独立的配色社区页面。
- 每个人可以上传自己的配色方案，集中展示。
- 大家可以给方案评分，并找到评分高的作品。
- 可以快速引用他人的方案，在工作台预览、修改为自己的方案。
- 先整理需求和设计原型，再由新对话中的 GPT-6.1 SOL、Ultra 实施。

以下是本轮建议，原型先验证这些交互；未宣称真实多用户服务已上线。

## 主流程

配色广场 → 方案详情 → 带入涂装台 → 创建自己的副本 → 自定义修改 → 保存私有方案 / 发布新作品。

“带入”创建一份新的、完整的 35 件方案。别人的作品、原作者的评分、自己已有的草稿，都不被静默覆盖。

## 页面设计

### 1. 配色广场

顶部仅保留「配色广场」「我的方案」「涂装台」与「发布方案」。

主体使用大尺寸、同相机与同灯光的真实模型缩略图。每卡包含：方案名称、作者、配色条、平均分与评分人数、引用次数，以及进入详情的入口。不要把各板的零件图作为主封面。

默认高分优先，另有「最新发布」。支持按名称/作者搜索和主色筛选。空结果明确显示重置按钮。模型锁定 XGO Duck V2，不增加没有实际选择价值的模型下拉框。

评分展示保留原始平均分和人数。默认排序使用平滑后的分数：(人数 × 均分 + 10 × 3.5) / (人数 + 10)，再以评分人数、发布时间和 ID 稳定排序。此为可调整的初始产品规则，3.5 与 10 是固定原型参数；它避免一票 5 分直接超过大量评价的高分作品。「高分优先」旁用说明提示排序考虑人数。

### 2. 方案详情

左侧是可旋转整机；右侧是名称、作者、说明、评分、色盘和真实耗材清单。页面优先动作是「带入涂装台」。

评分为 1–5 星，每账号每个发布版本一票，可以改分；修改时替换上一票，不增加人数。不能给自己的作品评分。原型使用一个明确标识的演示身份，数据只存本机；正式服务由后端强制约束。

有改版关系时展示「基于《原方案》· 原作者」，点击可回到来源版本。作者昵称不是所有权凭据。

### 3. 带入涂装台

在修改前校验 modelId/source_sha256、35 件 ID/UUID、颜色值、材料系列、耗材绑定及版本。缺零件、跨模型、跨材料、未知产品都不能直接进入可导出状态。

带入的是完整配色：颜色 + 产品绑定 + 来源版本。新建副本，原作品只读。原工作台的锁定应只保护原草稿，不能把社区完整方案静默导入成半套；新副本从独立锁定状态开始，旧草稿连同原锁定状态保留。

如果有尚未保存的修改，出现「保存当前草稿并继续 / 取消」，明确执行后才切换。原型的独立工作台使用独立 localStorage，不读取或覆盖真实工作台的草稿。

带入后继续使用已有项目色盘、连续点涂、就近调色、左右独立选择、对比、真实耗材和 3MF 导出能力。来源信息只作为元数据，不改几何尺寸、板结构或原材料。

### 4. 发布与我的方案

发布从当前已保存的方案创建不可变的版本快照。填写名称（必填）、一句说明（选填），预览封面和色盘，确认后发布。作品发布即允许社区用户复制到工作台继续改色，发布表单明确说明此点。

“保存”默认私有；“发布”才进入广场。我的方案区分草稿与已发布，后续可以撤下自己的作品。评分归属于发布版本；修改后发布为新版本或新作品，不能悄悄替换一套配色并继承其高分。

引用后的副本属于当前用户，仍保留 derivedFromSchemeId / derivedFromVersionId / sourceAuthor 的来源。发布改版时自动带上来源，不要求手填。点击预览不计引用；正式服务在服务器确认创建副本时计入，需幂等，避免重复提交放大计数。

## 原型范围

- 独立页面：`http://127.0.0.1:8876/community-prototype/`。
- 示例作品、作者、评分、引用数均为演示数据，有持续可见的提示。
- 读取同一份模型网格与官方耗材快照；缩略图及预览用真实网格渲染。
- 点击路径可运行：搜索/排序/筛选 → 详情/旋转 → 评分/改分 → 带入副本 → 单件换色 → 保存/模拟发布 → 返回广场找到作品。
- 原型不实现账号服务、真实评分服务器、公共文件上传、支付、关注、聊天或 MCP。
- 不改正式工作台的 localStorage 键；不向外部上传模型或配色。

## 正式多人版需要的基础能力（下一阶段）

账号与身份；方案及不可变版本存储；每用户每版本唯一评分；分页/搜索/排序；公开读取、本人编辑/撤下权限；校验与速率限制；缩略图存储；撤下/举报的最小处理流程。游客可以浏览，评分与发布需要登录。采用何种后端及部署域名，留待原型确认后决定。

建议数据：Scheme(id, ownerId, title, status, currentVersionId)，SchemeVersion(id, schemeId, modelId, sourceHash, colorsByPart, assignmentsByPart, derivedFromVersionId, createdAt)，Rating(versionId, userId, value)，Fork(id, fromVersionId, ownerId, idempotencyKey)。源 3MF 在服务端作为已知固定资产保存，社区提交颜色映射，不需要每个用户重复上传整份 3MF。

## 交给 SOL 的实施边界与验收

先完成真实工作台与社区原型的集成，本轮不部署公网、不接真实账户或评分后端。先读原型和现有实现，再落实以下要求：

1. 工作台有显眼的配色广场入口，广场可返回工作台，刷新/返回保留可解释的页面状态。
2. 展示至少 6 个不同的真实网格配色示例，使用完整 35 件映射与原始材料，不用生成图片冒充模型效果。
3. 搜索、颜色筛选、排序和空态可用；高分排序不能只比较一位小数。
4. 同一演示用户改评分不增加人数，不能给自己评分；刷新后状态可恢复。所有评分始终标为演示数据。
5. 引用先校验兼容性，新建完整副本；原作者方案、当前草稿和其他本地保存方案不丢失。
6. 在工作台独立改左件不会改右件；项目色组与来源方案不得被隐式覆盖。
7. 保存为私有方案后可以再次打开；模拟发布需显式确认，并保留来源；新版本的评分独立。
8. 真实 3MF 导出能保留不对称的逐件颜色、6 板/25 对象/35 件结构及原材质参数。源 `3D/` 条目字节一致。
9. 桌面与 390px 宽布局可完成主要流程；键盘能进入详情、评分、引用并关闭弹窗；无页面横向溢出。
10. 运行 README 所列全部检查和相关浏览器验收，逐项报告。技术通过不等同用户确认原型或实际多人上线。
