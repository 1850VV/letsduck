## 建议怎样应用

| 场景 | 每轮比较一个问题 | 验证方式 |
| --- | --- | --- |
| 涂装台 | 首屏模型与工具的面积分配；再单独讨论单件/配对范围与调色入口 | 相同模型、相同配色、相同选区并排比较；确认后测试真实点涂 |
| 配色广场 | 卡片上模型、评分、作者及引用入口的主次 | 同一组作品比较卡片；检查搜索空态及手机宽度 |
| 保存与发布 | 草稿、私有保存、模拟发布的区别是否清楚 | 正常、未保存、保存失败、已有草稿四种状态分别展示 |

建议顺序：读取项目现有颜色、字号和组件 → 制作两版画板 → 用户选定 → 写明具体改动 → 在实际应用中实现 → 用真实截图和短录屏对照设计 → 运行应用 README 所列检查。

先试用 `artifacts` 与逐项视觉验收的方式。完整工作流还包含强制 TDD、提交与审阅约定，是否采用应结合现有 AGENTS 规则另行评估。本轮没有新增项目工作规则。

## 重开与关闭

在机器鸭项目上下文目录运行。重开时使用工具打印的新链接，保留 `?key=` 参数。

```sh
npx --yes --package ryugi-artifacts@1.18.0 ryugi-artifacts start --json --project-dir '<project>' --artifact artboard/duck-ui-pilot
```

关闭查看服务，保留画板文件：

```sh
npx --yes --package ryugi-artifacts@1.18.0 ryugi-artifacts stop --json --project-dir '<project>'
```
