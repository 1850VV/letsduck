# 组装教程加载优化

## 目标与原因

目标是把进入组装教程到模型可操作的耗时至少降低 50%，保持 111 步的提示、时长、模型和材质。

原实现导入 `fine-cues.mjs` 时，通过 `FINE_STEPS` 计算整个教程的提示集合。每一步会取 9 个姿态样本，螺丝和轴承还会二分查找动作区间。它在页面显示前遍历全部 111 步，阻塞主线程约 2.5 秒。CPU 采样中，主要时间花在姿态快照、复制和接线变换。

现在聚焦判断按当前步骤查询，播放时长也按需解析一次并缓存。已有提示缓存继续复用。没有减少模型面数、降低画质、改动动作或提前取消素材加载。

## 实测

2026-10-24，本机 macOS，Playwright 1.58.2 管理的 Chromium 145.0.7632.6，1440×1000，默认画质，同一套本地资产和个人版服务。基线为 `1e2e89a`；候选为本变更。先完成其他测试，再顺序测量基线和候选，避免同时跑 CPU 测试。

从首页点击「开始组装」，以组装页导航开始到 `data-ready` 后两次动画帧回调为首帧指标。每个版本创建 3 个新浏览器上下文，每个上下文分别测首次进入和返回首页后再次进入。下表为各 3 次的中位数。

| 指标 | 基线 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 首次进入：模型 ready | 2.96 秒 | 0.58 秒 | 80% |
| 首次进入：首帧可操作 | 3.12 秒 | 0.75 秒 | 76% |
| 再次进入：首帧可操作 | 3.10 秒 | 0.68 秒 | 78% |

这是本机实测。新上下文不等于操作系统和 GPU 缓存全冷启动；新浏览器进程、不同 GPU、设备和网络的结果可能不同。初次诊断时曾测到 5.07 秒的首帧，其中还包含较长的首次 GPU 渲染。本变更消除的是整套提示的同步预计算，不承诺所有设备都在 1 秒内完成。

## 验收证据

| 条件 | 结果 |
| --- | --- |
| 首帧耗时减少至少 50% | 首次进入减少 76%，再次进入减少 78% |
| 提示和时长不变 | 在真实浏览器逐项比较全部 111 步的完整提示、聚焦状态和时长，与基线一致 |
| 阶段跳转和模型保持 | 14 个阶段跳转状态、整机完成态及硬件资源状态与基线一致 |
| 显示效果保持 | 同尺寸起始画面和整机预览，各 5,760,000 个颜色通道的差异均为 0 |
| 不再扫描未访问步骤 | 浏览器回归在基线失败；候选启动只分析第 0 步，直跳整机预览后只分析第 0、110 步 |

## 复测

先按 README 导入本地资产并启动个人版。浏览器回归只用新建的管理浏览器上下文，结束后关闭上下文和浏览器；不会改动实际用户方案。

```sh
npm ci
node --test tests/*.mjs tests/assembly/*.mjs
DUCK_BROWSER_URL=http://127.0.0.1:8876 node tests/assembly-loading-browser.js
python3 -m unittest discover -s tests -p test_personal.py -v
.venv/bin/python scripts/publication_audit.py
.venv/bin/python -m unittest discover -s tests -v
```

本轮 Node 220 项通过、3 项跳过（可选压缩资产未生成）；Python 59 项通过、18 项 MySQL 检查因未配置测试库跳过；系统 Python 个人版 10 项通过。最初复用的旧虚拟环境缺少 `httpx2`，4 个测试模块无法导入；在隔离虚拟环境安装仓库锁定的开发依赖后，完整 Python 检查通过。

浏览器回归输出保存在被忽略的 `output/playwright/assembly-loading/`。素材、截图、用户数据和采样文件不进入源码发行版。用户对本机实际体验的验收仍需实际点击确认。
